# Agent instructions

These are the rules for changing myakiba. Each rule in the table below names the check that fails when you break it, or says it is `judgment` when no check exists. `GLOSSARY.md` defines the domain words.

## Before you push

Run these from the repo root. CI's Validate job runs the same checks, each as its own step.

- `bun run check` checks formatting, this file's rule table and the lint budget.
- `bunx turbo run check-types` type-checks every package and fails when the server or web app turns off a strict flag.
- `bun run test` runs every package's tests and the tooling tests. The order tests need `TEST_DATABASE_URL`, and they create and drop their own database.
- `bun run knip` checks undeclared dependencies and dead files and exports against their budget.

## Budgets and approvals

The lint budget (`tools/oxlint/budget.json`) and the knip budget (`knip-budget.json`) list the hits that existed when each check started. Counts only go down. A new hit fails the check, so fix the code. When you fix a budgeted hit, lower or remove its entry in the same commit, because a count below its budget also fails.

A commit that raises a budget or changes the gated tooling needs a `Lint-Budget-Approved-By: <approver>` Git trailer. Gated tooling is:

- for lint: any oxlint config or ignore file, `tools/oxlint/`, `scripts/lint-budget.ts`, `patches/`, and the oxlint, oxlint-tsgolint, ultracite and oxc-parser versions in `package.json` and `bun.lock`, with overrides, resolutions and patched dependencies;
- for knip: `knip.json`, `scripts/knip-budget.ts`, `pnpm-workspace.yaml`, and the `knip` and `workspaces` keys of `package.json`.

Lowering a budget needs no trailer. Merge one branch at a time, because merges follow these rules:

- A two-parent merge counts through its own conflict-resolution changes.
- For lint, a merge of three or more branches always needs the trailer, even a clean one, because Git shows no own changes for it.
- For knip, a merge of three or more branches fails, trailer or not, when `knip.json`, `knip-budget.json`, `scripts/knip-budget.ts`, `pnpm-workspace.yaml` or the `knip` or `workspaces` key of `package.json` differs from any parent. A clean one passes.

Get the approval before you write the trailer, and write it in the approver's words. A person approves with their name. A program root that countersigns under the operator's grant writes `Lint-Budget-Approved-By: root (<what it approved and why>)`.

The trailer is a record, not enforcement. The scripts check that a trailer is there, not who wrote it, and CI runs code the PR controls: the workflow, package scripts, a `bunfig.toml` preload, tsconfig path remaps and install scripts. Only a required review on the tooling files, such as CODEOWNERS, would enforce approval, and the repo has none yet. So treat every gated change as one a person must review.

## Scraper code

Leave scraper code as it is: `apps/worker`, the sync, item-resync and data-transfer routers, and the web sync and import screens. The browser extension replaces it. Its existing lint hits stay in the budgets, and `apps/worker` stays off the strict flags.
